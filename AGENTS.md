# AGENTS.md

Guidance for coding agents working in this repository.

## Project

Remora is a type-safe Python DSL for Wireshark/tshark capture analysis. It drives tshark subprocesses directly (no pyshark): field access is statically typed via `.pyi` stubs, display filters are built from expression trees instead of strings, and predicates are pushed down to tshark where possible. A DuckDB workspace (`remora[workspace]`) caches dissected fields as columns so repeat queries never re-parse the pcap.

Work is organized by milestone epics (#40 M1 kernel, #41 M2 codegen, #42 M3 polish, #43 M4 DuckDB workspace). Design rationale lives in the issue that made the decision. When this file cites `#<n>`, `gh issue view <n> --comments` has the full argument.

Durable documentation lives in `docs/`. Each document and the module it describes are two statements of one machinery, so a change to one belongs in the other.

| Document | Covers |
| --- | --- |
| `docs/semantics.md` | Absent-field truth table, regex support matrix, portable-text guard, `-T fields` escape table |
| `docs/workspace.md` | Cache keys, hit/backfill/refuse, modes and locking, `compact()`, export, annotations, streams, attach |
| `docs/codegen.md` | Docker regeneration recipe, drift-check triage, `psdsl gen` worked example |

## Commands

Everything runs through uv (Python ≥3.10; the CI matrix covers 3.10 through 3.14):

```bash
uv sync                                        # install deps
uv run pytest                                  # full test suite
uv run pytest tests/test_planner.py -v         # one file
uv run pytest tests/test_fields.py::TestScalarInstanceAccess::test_static_types -v  # one test
uv run pytest -m "not integration"             # skip tests needing a real tshark binary
uv run mypy --strict src tests                 # typecheck (tests included — this is the CI gate)
uv run ruff check .                            # lint
uv run ruff format --check .                   # format check (also formats code fences in docs/*.md)
uv run mypy --strict --python-version 3.12 .github/scripts/check_stub_resolution.py  # extras stubs, editable layout
```

The CI gate is all five: `ruff check`, `ruff format --check`, `mypy --strict src tests`, the stub check, and `pytest`. Run it before committing.

- The stub check keeps `from remora.proto.wlan import WLAN` typed in an editable or multi-root layout (#77). Its `--python-version 3.12` only selects typeshed semantics, so the one step runs unchanged on every interpreter.
- mypy verifies the `assert_type(...)` calls in `tests/`. Put them before runtime asserts, because `assert x == value` narrows a type and can break a later `assert_type`.
- CI's `checks` job installs Ubuntu 24.04's stock tshark (4.2.2), not the codegen pin. Behavior asserted against a live binary must hold on both, so measure on 4.2.2 first.
- `tests/conftest.py` provides `FakePacket`, the standard `RawPacket` double, and the dependency guard. Workspace suites `importorskip("duckdb")`, and `REMORA_REQUIRE_DUCKDB=1` / `REMORA_REQUIRE_TSHARK=1` (set in CI) turn a missing dependency into a failed run instead of a skipped one.

## Workflow

- One PR per issue. Branch `feat/issue-<n>-<slug>` (or `feat/<n>-<slug>`), and put `Closes #<n>` in the PR body. PRs are squash-merged, so merged local branches need `git branch -D`.
- Process artifacts are issue comments, not repository files. Design docs, specs, plans and progress notes go to `gh issue comment <n>`. Only durable documentation (`docs/*.md`, ADRs, `AGENTS.md`) is committed. `docs/superpowers/` is gitignored scratch space.

## Cross-cutting invariants

- Loud beats silent. Parse errors raise, non-injective naming is checked and refused, a stale or foreign workspace file is refused at open, and a backend that cannot express an expression raises its `Unsupported*` error rather than approximating.
- Storage-format changes are never tweaks. Changing a column type, a layout column, a cache-key scheme or a separator byte bumps `SCHEMA_VERSION` or the key-scheme prefix, so older files are refused visibly instead of misread.
- Absence is a value, not an exception: `()` from `get_raw`, `None` from scalar instance access, `()` from multi instance access. The one exception is `FieldNotProjectedError` for a field outside a `-T fields` projection, which is a caller bug rather than absence.
- Names are not re-derived at runtime. `_table_` stores the full tshark name, so nothing maps attribute names to tshark names or back. The pairing tests in `tests/test_proto_seed.py` are the frozen-format contract for generated modules; keep them passing unmodified.
- Underscore-prefixed attributes on protocol classes are reserved, and `_table_` carries the `ClassVar[FieldTable]` annotation (ruff RUF012).

## Architecture

Query data flow: **Expr IR → planner → tshark argv → reader → RawPacket → protocol view / predicate**. The workspace is a second surface over the same IR: **Expr IR → SQL backend → DuckDB scan over materialized columns → Row**.

### Core: `src/remora/`

- `expr.py` is the immutable expression IR and a leaf module that imports nothing from remora. `__bool__` raises so `and`/`or`/chained comparisons fail loudly (use `&`/`|`/`~`, and parenthesize comparisons). There is no `Ne` node: `!=` builds `Not(Comparison(EQ, ...))`, which makes Wireshark's multi-value `!=` pitfall unrepresentable. `FieldRef` is deliberately unhashable (`__eq__` returns an `Expr`), so dedup by `.name`.
- `values.py` is the single mapping from tshark ftypes to Python types and parsers. Parse errors raise `ValueError`, and unknown ftypes fall back to `str`. `coerce_literal` normalizes user literals at compile time for every backend.
- `fields.py` is the contract hub. `RawPacket` is the minimal packet protocol: `get_raw(name) -> tuple[str, ...]`, with `()` meaning absent. `Field`/`MultiField` are dual-mode descriptors. Class access returns a `FieldRef[T]`; instance access returns `T | None` (scalar) or `tuple[T, ...]` (multi). Multiplicity lives in the descriptor *class* because `@overload` can only express the return type per class.
- `planner.py` is a pure two-level pushdown that never spawns tshark. Pushable conjuncts become `-Y`, a projection enables `-T fields`, and opaque lambdas force `-T ek`. Conjuncts that fail to push become residual Python predicates.
- `capture.py` is the public pcap-path surface. `Capture` is an immutable builder: `filter()` accumulates terms, and `select()` sets the projection that makes fields mode reachable (#105). Iteration plans, spawns tshark, applies the residual predicate, and closes the subprocess however it ends.

### Compile backends: `src/remora/compile/`

Three backends lower one `Expr`, and `docs/semantics.md` states where they agree and disagree. The planner catches `UnsupportedExprError` from the dfilter backend and hands the conjunct to the predicate backend, so a dfilter refusal costs only pushdown.

- `dfilter.py` renders Wireshark display-filter strings. `!=` renders `!(f == v)`. A NaN literal is refused wherever a float reaches the renderer, because Wireshark lexes `nan` as a literal whose matching is ftype- and version-dependent (#90); `inf`/`-inf` push down unchanged.
- `predicate.py` compiles Python predicates over `RawPacket`. It is the end of the fallback chain and the reference semantics, including any-occurrence matching on multi-value fields.
- `sql.py` produces a DuckDB predicate string plus bound parameters (#29). It is import-pure and never imports duckdb. Column name, SQL type and multiplicity come from `workspace.naming`/`workspace.types` and are not re-derived. These rules must survive any edit:
  - Every literal takes the one path `_coerce` → `_encode_coerced`, because the value between them is what the NaN test and the range-inversion check read (#89).
  - Multi-value columns keep any-occurrence semantics (`list_contains` / `list_filter`). `!=` renders `NOT (...)`; SQL `<>` is never used on a list column.
  - A NaN literal compiles to `FALSE`, and `>`/`>=` on a `DOUBLE` column (per `types.COLUMN_TYPES`) carry `NOT isnan(...)`, so a stored NaN is excluded as Python excludes it.
  - NULL harmonization (#36): a NULL-able leaf is wrapped `coalesce(<leaf>, FALSE)` only when a `Not` will invert it, and only at the leaf. Coalescing a subtree gets nested negation wrong, and coalescing a positive leaf blocks scan-level filter pushdown for no gain.
  - `matches` compiles to `regexp_matches(col, ?, 'i')` behind the portable-text guard and `re2.py`'s ASCII-only pattern rule. The two are only sound together, so do not relax one without the other.
  - `UnsupportedSqlExprError` covers unknown nodes, patterns RE2 cannot run, and `contains` on a BLOB column. Malformed literals stay `ValueError`/`TypeError`, as in the sibling backends.

### Reader: `src/remora/reader/`

- `process.py` owns tshark subprocess lifecycle and nothing else. A daemon thread drains stderr to avoid pipe deadlock, and `close()` terminates, kills and reaps so no orphan survives.
- `fields_reader.py` parses `-T fields`. Its framing bytes are chosen against tshark's C-style escaper and must not be changed casually. The column separator `UNIT_SEP` (`0x0b`) must be a byte the escaper *replaces*, so no value can forge it. The occurrence aggregator `OCC_SEP` (`0x1e`) must be a byte the escaper *leaves alone*, or it arrives as a two-character escape and never splits. Value unescaping runs only on tshark ≥ 4.4 (`escaping_is_reversible()`, with an unknown version counting as old), because 4.2.x escaping is not injective. Changing either separator changes every stored workspace cache key (#74).
- `ek_reader.py` parses `-T ek` NDJSON. The key mapping is `layers["ip"]["ip_ip_src"]` (layer + `_` + dots→underscores).

### Protocol modules: `src/remora/proto/`

- `_meta.py` and `__init__.py` are the only hand-written files. `_meta.py` defines the frozen compact-table format: a class sets `_proto_` and `_table_: ClassVar[FieldTable]` (attr name → `(tshark_name, ftype, multi 0/1)`), and descriptors materialize lazily on first access so a 10k-field module imports for free.
- Every other module is generated (#19) with a sibling `.pyi` stub. Regenerate with `uv run python -m remora.codegen write` under the pinned tshark, natively on the host architecture and not under emulation. Regeneration has been architecture-neutral since #97, and `codegen-arch-verify.yml` proves it on both architectures. Committed bytes are emitter-exact: ruff ignores E501 under `proto/`, and the formatter skips the tree.
- `codegen.toml` lists the core set, the curated multi-value fields, and the extras shipped as `remora-<extra>` distributions under `packages/`. Extras graft into `remora.proto` via `pkgutil.extend_path`. `remora.proto.__getattr__` imports installed extras lazily and raises an `ImportError` naming the extra for a missing one. `remora[all]` is derived rather than listed; `tests/test_packaging.py` computes it.
- Every distribution ships its own `remora/py.typed` (#77). Uninstalling any one of them deletes the shared marker in a wheel layout, an accepted price that only affects type checking.

### Codegen: `src/remora/codegen/`

- `parse.py` turns a `tshark -G fields` dump into frozen dataclasses. Malformed, unknown and duplicate lines become collected `ParseWarning`s (first occurrence wins) rather than silent drops. Tests assert exact record counts against `tests/data/g_fields_sample.txt`.
- `mangle.py` is the frozen abbrev → attribute-name policy. It is not injective (dots and hyphens both become `_`), so emitters must detect per-protocol duplicate mangled names.
- `emit.py` renders one protocol's `.py`/`.pyi` pair, byte-deterministic in input field order, so reproducible bytes need `fingerprint.py`'s canonical dump order. Multiplicity has no `-G fields` signal, so the multi-abbrev set is caller-supplied. Collisions resolve first-wins, except that a data field displaces an earlier `FT_NONE` marker, and every collision path records an `EmitWarning`.
- `fingerprint.py`'s `env:` line hashes only the `(name, version, type)` columns of `tshark -G plugins`, dropping the path column that embeds the multiarch triplet.

### Workspace: `src/remora/workspace/`

`docs/workspace.md` is the user-facing account. These are the implementation invariants.

- Connections. `workspace.py` is the only module that opens a DuckDB connection; every other module takes one. Only three modules reach outside the database: `cachekey.py` reads the capture, `export.py` stats the destination, and `materialize.py` runs tshark. duckdb is imported lazily inside the connect helper, so importing the package never imports it, and a missing duckdb raises `ImportError` naming `pip install 'remora[workspace]'`.
- Layout (`schema.py`). `iter_ddl()` is the single source of the layout, and `create_schema()` executes exactly those statements, idempotently. `iter_scratch_ddl()` holds session-scoped `TEMP` DDL. Tests freeze this: only `schema.py` (plus the visible `DDL_SCRATCH_FILES` exemption set) may contain a `CREATE` head, and the heads inside `schema.py` must equal `iter_ddl()`. `SCHEMA_VERSION` is 2, `check_compatible` accepts only the exact version, and there is no migration. Any column added to an existing table is a bump, because `create_schema` is `IF NOT EXISTS`-only. The opener calls both `create_schema` and `check_compatible`. Packet data lives in `main` (`pkts`, `streams`, `annotations`) and the catalog in `meta`. `pkts` has no `PRIMARY KEY`, because an ART index taxes bulk append; `frame_number` is the row key by convention. Every catalog probe is pinned to `current_database()` so an attached database cannot vouch for or collide with the current one.
- Naming and types. `naming.column_name` keeps the full abbrev, lowercased, and is not injective, so `find_collisions` before materializing a field set is mandatory, with `meta.fields.column_name UNIQUE` as backup. The row-key columns `frame_number`/`frame_time` (`naming.SKELETON_COLUMNS`) get no registry entry. `types.COLUMN_TYPES` is frozen, because a column type is a storage format, and it covers exactly `values.FTYPE_TABLE`. Addresses are integers (`FT_IPv4` → `UINTEGER`, `FT_IPv6` → `UHUGEINT`) so a subnet test is a zone-map-friendly `BETWEEN`. Timestamps are naive UTC `TIMESTAMP`, never `TIMESTAMPTZ`. `FT_IPv6` alone encodes to decimal text rather than `int`, because DuckDB unifies a list's inferred element types before casting and a list mixing values below 2^63 and above 2^127 fails to bind. Do not broaden it. An absent scalar encodes to `None` and an absent multi to `[]`, since `list_contains(NULL, x)` is `NULL`. A scalar-declared field occurring twice raises `ValueError`.
- Cache keys (`cachekey.py`, #27). `fingerprint_pcap` hashes `st_size`, `st_mtime_ns` and the first and last 64 KiB, not the whole file. Its blind spot, an in-place middle edit preserving size and mtime, is pinned by a named test as an accepted trade-off. `make_cache_key` digests fingerprint, sorted-deduplicated field set, dfilter (`None` and `""` distinct), tshark version and the full effective argv under the `ck1:` prefix. It returns a `CacheKeyRecord` so what was hashed and what gets written cannot drift. A lone surrogate is refused with `ValueError` before the capture is read, because `VARCHAR` cannot hold it.
- Materialize (`materialize.py`, #31/#32). One `write()` transaction wraps `materialize_into`. A `filter` must compile fully to `-Y`. There is no residual-predicate fallback, because the cache key records only the dfilter. The projection always asks for `frame.time_epoch`; `frame.number`/`frame.time` get no column. Rows are appended in bounded `executemany` batches, and Arrow is refused because of the `FT_IPv6` hazard. `TsharkRunner` and `tshark_version` are injectable so the unit suite spawns nothing. A workspace records exactly one cache key, and a repeat request is decided component by component rather than digest against digest. Fingerprint, dfilter, tshark version and argv-minus-`-e`/`-r`/`-Y` must match. Then requested ⊆ materialized is a **hit**, a superset is a **backfill** (rescan only the new fields, then `UPDATE ... WHERE frame_number = ?` after a set-based row-key alignment check), and anything else is `MaterializationMismatchError` naming each changed component. Reuse requires an intact workspace: one key, key and `meta.fields` agreeing, and every registered plus skeleton column present in `duckdb_columns()` with the declared type.
- Workspace class (`workspace.py`, #28). `Workspace(path, mode="ro")` defaults to read-only because one long-lived read-write connection blocks every other process's reads under DuckDB's single-writer lock. `ro` holds one long-lived read-only connection. `rw` holds none between operations: `write()` opens one around exactly one transaction, and `read()` in rw mode opens read-write because DuckDB refuses two live same-process connections with different configurations. So an rw-mode read holds the exclusive lock for its whole duration, and a read nested in `write()` runs on its own connection and does not see uncommitted rows. rw mode runs `create_schema` only on a database with no user objects of any kind, so a foreign file is refused rather than half-upgraded. `compact()` rewrites into a sibling `.compacting` temp via `COPY FROM DATABASE` and `os.replace`s it in while the source's exclusive lock is still held, so no commit can land in a gap and be discarded. The temp inherits the source's mode bits, the work happens on the `realpath`, stale temps are cleaned only under the lock, and Windows gets a `WorkspaceError` naming the limitation (#85). Same-process coordination between `write()`/rw-`read()` and `compact()` is a module-level registry of counters and a flag, not a connection, keyed by file identity (`(st_dev, st_ino)`). The identity is recomputed per operation because `compact()` swaps the inode and holds the flag under both identities across the swap. What remains uncovered is a hard-linked alias, which points at the old inode after a compact through another name.
- Export (`export.py`, #34). `export_parquet(table, path)` is one `COPY ... TO (FORMAT PARQUET)` inside a `read()`, so it works in ro mode. `table` is validated against the closed `EXPORTABLE_TABLES` set, because identifiers cannot be bound. The destination is compared by file identity against the database file and its `.wal`, since an overwritten `.wal` is discarded silently on open and takes committed rows with it. The write goes into a private `0700` `mkdtemp` directory and is renamed onto the destination, so a link planted after the check is replaced rather than written through, and a failed `COPY` leaves the previous file intact. Two types are rewritten, at list depth too: `UHUGEINT` → `VARCHAR`, because duckdb writes 128-bit integers to Parquet as `double`, and `INTERVAL` → `VARCHAR`, because Parquet's interval is millisecond-resolution. The export needs duckdb alone; pyarrow is dev-only here.
- Annotations (`annotations.py`, #30). A stream annotation is keyed by `(protocol, target_id)` because tcp and udp each number streams from zero. A packet annotation is keyed by frame number alone, since one workspace holds one capture. `annotation_id` is a high-water mark in `meta.info` (`next_annotation_id`) advanced inside the caller's transaction. It is not a sequence, which is unavailable on an existing file, and not `max+1`, which is non-unique across threads and non-monotonic after a delete. A pre-existing file with annotation rows but no mark is refused rather than seeded; an empty one is seeded silently. Orphans are kept but flagged. `orphaned` is derived at read time via EXISTS rather than a join, because `pkts` has no key. `delete_orphan_annotations` is the one explicit removal, and `remove_annotations` refuses a call with no filters.
- Streams (`streams.py`, #33). `build_streams()` is one set-based `INSERT ... SELECT ... GROUP BY` per protocol, not a Python loop, keyed by `(protocol, stream_id)`. Endpoints come from the stream's first frame in one `first(... ORDER BY frame_number)` aggregate so they describe one packet, and `byte_count` sums `frame.len` to match `tshark -z conv`. The prerequisite rule is all of `REQUIRED_FIELDS`, both protocols', or nothing, checked against `meta.fields` before any SQL touches `pkts`; `MissingStreamFieldsError` names the missing abbrevs. Addresses are IPv4-only, and NULL marks a non-IPv4 first frame. Rebuild is delete-then-reinsert inside one transaction.
- Query (`query.py`, #35). It is a separate class from `Capture` on purpose: one IR, two surfaces, and the type in hand says which engine pays. It is immutable and lazy, and nothing touches the database until `__iter__`, `arrow()` or `sql()`. Every field the query mentions is checked against `meta.fields` before any SQL is generated, and `FieldNotMaterializedError` names every missing one. Each ref's ftype and multiplicity are compared with the stored declaration (`FieldDeclarationMismatchError`) both at compile time and in `Row.get`/`get_all`, because a wrong ftype can encode to something the column holds and silently match nothing. The row key alone skips the catalog lookup (`_ROW_KEY_FTYPES`) and is always projected first. Decoding follows the stored `FieldRecord`, not the caller's ref. `Row` is not a `RawPacket`: access is `row.get(IP.src)` / `row.get_all(TCP.port)`, with multiplicity checked at access time. `__iter__` calls `fetchall()` inside one `read()` and decodes afterwards. It deliberately does not stream, because paging would hold the connection (in rw mode, the exclusive lock) across the consumer's loop and in ro mode would collide with a nested query on the one held connection. `arrow()` casts `UHUGEINT`/`UHUGEINT[]` to `VARCHAR` because DuckDB exports it through Arrow as signed `decimal128(38, 0)`; pyarrow is the `remora[arrow]` extra. `Query` never enters the write API, and a test pins that. Parity with the pcap path is asserted operator by operator in `tests/integration/workspace/test_parity_matrix.py` (#38). `test_benchmark.py` (`slow`) asserts `MIN_SPEEDUP = 5.0` for a cached repeat query against the projected `Capture.select(...)` baseline, an order of magnitude under the measured speedup so a shared runner cannot flake it. The `-T ek` side is printed and never asserted (#105). Raw SQL passthrough and joins are out of scope; `Workspace.read()` hands out the connection.
- Attach (`attach.py`, #37/#100). Every attach is `(READ_ONLY)` in either mode. An attach belongs to the database instance, not the connection, so `rw` mode loses it between operations and `Workspace` replays recorded attachments onto every connection it opens (in `write()` before `BEGIN`). Each replayed ATTACH is validated **after** it is issued, since a pre-ATTACH check only describes whatever was at the path when it ran. Replay is all-or-nothing over the batch (`roll_back_attachments`), and a replay failure becomes `WorkspaceError`/`SchemaVersionError` naming the alias and path. A live alias binds to the file that was attached, not the pathname, so `detach` and attach again is the remedy for a replaced peer. Alias comparison is case-insensitive at the one door aliases enter through, while the `_attachments` record stays case-sensitive. A colliding alias found by DuckDB's binder is classified by message text (`is_duplicate_database_error`) because `attach.py` never imports duckdb, and a test pins the live message so a reworded duckdb fails loudly. A read-only attach holds a shared read lock while a connection carrying it is open. `Query(alias=)` changes exactly the table and the `meta.fields` it validates against, re-checked at every execution. `Query` stays single-table; a cross-capture join is ordinary SQL over `Workspace.read()`.
