# AGENTS.md

Guidance for coding agents working in this repository.

## Project

Remora is a type-safe Python DSL for Wireshark/tshark capture analysis. It drives tshark subprocesses directly (no pyshark): field access is statically typed via `.pyi` stubs, display filters are built from expression trees instead of strings, and predicates are pushed down to tshark where possible. A DuckDB workspace (`remora[workspace]`) caches dissected fields as columns so repeat queries never re-parse the pcap.

Work is organized by milestone epics (#40 M1 kernel, #41 M2 codegen, #42 M3 polish, #43 M4 DuckDB workspace); each epic issue defines the execution path and dependency graph.

Durable documentation lives in `docs/`:

| Document | Covers |
| --- | --- |
| `docs/semantics.md` | Absent-field truth table, regex support matrix, portable-text guard, `-T fields` escape table |
| `docs/workspace.md` | Cache keys, hit/backfill/refuse, modes and locking, `compact()`, export, annotations, streams, attach |
| `docs/codegen.md` | Docker regeneration recipe, drift-check triage, `psdsl gen` worked example |

Each of those documents and the module it describes are two statements of one machinery: a change to one belongs in the other.

## Commands

Everything runs through uv (Python ≥3.10; CI matrix is 3.10–3.14):

```bash
uv sync                                        # install deps
uv run pytest                                  # full test suite
uv run pytest tests/test_planner.py -v         # one file
uv run pytest tests/test_fields.py::TestScalarInstanceAccess::test_static_types -v  # one test
uv run pytest -m "not integration"             # skip tests needing a real tshark binary
uv run mypy --strict src tests                 # typecheck (tests included — this is the CI gate)
uv run ruff check .                            # lint
uv run ruff format --check .                   # format check (also formats code fences in docs/*.md)
uv run mypy --strict --python-version 3.12 .github/scripts/check_stub_resolution.py  # extras stubs, editable layout
```

The CI gate is all five: `ruff check`, `ruff format --check`, `mypy --strict src tests`, the extras stub check, and `pytest`. Run the full gate before committing.

Notes on the gate:

- The stub check keeps `from remora.proto.wlan import WLAN` typed in an editable or multi-root layout (#77). It fails if any extras distribution loses its own `remora/py.typed`, a loss a wheel install masks because every distribution unpacks into one `site-packages/remora/`. Its `--python-version 3.12` selects typeshed semantics only, so the one step runs unchanged on every interpreter in the matrix.
- Static typing assertions are part of the test suite: `assert_type(...)` calls in `tests/` are no-ops at runtime and are verified when mypy checks the test files. A preceding `assert x == value` can narrow a type and break a later `assert_type`, so put `assert_type` before runtime asserts.
- CI's `checks` job installs Ubuntu 24.04's stock tshark (4.2.2), not the codegen pin. Behavior asserted against a live binary must hold on both; measure on 4.2.2 before asserting it.

## Workflow

- One PR per issue. Branch `feat/issue-<n>-<slug>` (or `feat/<n>-<slug>`), PR body includes `Closes #<n>`. PRs are squash-merged, so merged local branches need `git branch -D`.

## Architecture

Data flow for a query: **Expr IR → planner → tshark argv → reader → RawPacket → protocol view / predicate**. The workspace is a second surface over the same IR: **Expr IR → SQL backend → DuckDB scan over materialized columns → Row**.

### Core: `src/remora/`

- **`expr.py`** — immutable expression IR, deliberately a leaf module (imports nothing from remora). Comparisons on fields build `Expr` trees; `__bool__` raises so `and`/`or`/chained comparisons fail loudly (use `&`/`|`/`~`, parenthesize comparisons). There is **no `Ne` node**: `!=` builds `Not(Comparison(EQ, ...))`, making Wireshark's multi-value `!=` pitfall unrepresentable. `FieldRef`s are intentionally unhashable (`__eq__` returns an `Expr`); dedup by `.name`.
- **`values.py`** — the single source of truth mapping tshark ftypes (`"FT_IPv4"` …) to Python types and parse functions. Parse errors raise `ValueError`; unknown ftypes fall back to `str`. `coerce_literal` normalizes user literals at compile time for every backend.
- **`fields.py`** — the contract hub. `RawPacket` is the minimal packet protocol: `get_raw(name) -> tuple[str, ...]` with `()` meaning absent. `Field`/`MultiField` are dual-mode descriptors: class access (`IP.src`) returns a `FieldRef[T]` for building expressions; instance access (`pkt[IP].src`) returns `T | None` (scalar) or `tuple[T, ...]` (multi). Multiplicity is encoded in the descriptor *class* because `@overload` can only express the return type per class.
- **`planner.py`** — two-level pushdown, a pure decision that never spawns tshark. Pushable conjuncts become a `-Y` display filter; a projection enables `-T fields`; opaque lambdas force `-T ek` whole-packet fallback. Conjuncts that fail to push become residual Python predicates.
- **`capture.py`** — the public pcap-path surface. `Capture` is an immutable builder: `filter()` accumulates terms, `select()` sets the projection that makes the planner's fields mode reachable (#105), and iteration plans, spawns tshark, and yields packets passing the residual predicate. A field outside a fields-mode projection raises `FieldNotProjectedError` (a caller bug, not absence); ek mode answers every field. `__iter__` closes the subprocess however iteration ends.

### Compile backends: `src/remora/compile/`

Three backends lower the same `Expr`. The planner catches `UnsupportedExprError` from the dfilter backend and hands the conjunct to the predicate backend, so a dfilter refusal costs only pushdown. `docs/semantics.md` is the durable statement of where the three agree and disagree.

- **`dfilter.py`** — renders Wireshark display-filter strings. `!=` always renders `!(f == v)`. An IEEE-754 NaN literal is refused (`UnsupportedExprError`) wherever a float reaches the renderer: Wireshark lexes the text `nan` as a literal and what it then matches is ftype- and version-dependent, so it is not self-protecting (#90). `inf`/`-inf` push down unchanged.
- **`predicate.py`** — compiles Python predicates over `RawPacket`; the end of the fallback chain and the reference semantics, including any-occurrence matching on multi-value fields.
- **`sql.py`** — lowers the IR to a DuckDB predicate string plus bound parameters (#29). Import-pure: plain strings and Python values, never duckdb. Column name, SQL type and multiplicity come from `workspace.naming`/`workspace.types`, never re-derived. Rules that must survive any edit:
  - Every literal takes one two-step path, `_coerce` then `_encode_coerced`, because the value between them is what the NaN test and the range-inversion check read (#89).
  - Multi-value columns keep any-occurrence semantics (`list_contains` / `list_filter`); `!=` renders `NOT (...)` and never SQL `<>` on a list column.
  - A NaN literal compiles to the constant `FALSE`; `>`/`>=` on a `DOUBLE` column carry `NOT isnan(...)`, so a stored NaN is excluded as Python excludes it. Which columns are `DOUBLE` is read from `types.COLUMN_TYPES`.
  - NULL harmonization (#36): a NULL-able leaf is wrapped `coalesce(<leaf>, FALSE)` only when a `Not` will invert it, and only at the leaf. Coalescing a subtree gets nested negation wrong; coalescing a positive leaf blocks scan-level filter pushdown for no semantic gain.
  - `matches` compiles to `regexp_matches(col, ?, 'i')` behind the portable-text guard (refuse non-ASCII, newline- or VT-bearing values) and `re2.py`'s ASCII-only pattern rule. The two are only sound together; do not relax one without the other.
  - `UnsupportedSqlExprError` covers unknown nodes, patterns RE2 cannot run, and `contains` on a BLOB column. Malformed literals stay `ValueError`/`TypeError` as in the sibling backends.

### Reader: `src/remora/reader/`

- **`process.py`** owns tshark subprocess lifecycle only: stderr drained by a daemon thread to avoid pipe deadlock; `close()` terminates/kills/reaps so no orphans survive.
- **`fields_reader.py`** parses `-T fields` output. Framing bytes are chosen for the two sides of tshark's C-style escaper and must not be changed casually: the column separator `UNIT_SEP` (`0x0b`) must be a byte the escaper *replaces* so no value can forge it, and the occurrence aggregator `OCC_SEP` (`0x1e`) must be a byte the escaper *leaves alone* or it arrives as a two-character escape and never splits. Both choices hold on 4.2.2, 4.4 and 4.6. Value unescaping runs only on tshark ≥ 4.4 (`escaping_is_reversible()`), because 4.2.x does not double a literal backslash and its escaping is not injective; an unknown version counts as old. Changing either separator changes every stored workspace cache key (#74).
- **`ek_reader.py`** parses `-T ek` NDJSON; key mapping is `layers["ip"]["ip_ip_src"]` (layer + `_` + dots→underscores).

### Protocol modules: `src/remora/proto/`

- `_meta.py` defines the **frozen compact-table format**: a class sets only `_proto_` and `_table_: ClassVar[FieldTable]` mapping attr name → `(tshark_name, ftype, multi 0/1)`; descriptors are materialized lazily on first access so a 10k-field module imports for free. `_meta.py` and `__init__.py` are the only hand-written files.
- Every other module is a generated artifact (#19) with a sibling `.pyi` stub that shadows it for type checkers. Regenerate with `uv run python -m remora.codegen write` under the pinned tshark, natively on the host's architecture and never under emulation: regeneration is architecture-neutral since #97, and `.github/workflows/codegen-arch-verify.yml` proves it on both architectures whenever the fingerprint scheme or pin changes. Committed bytes are emitter-exact: ruff ignores E501 under `proto/` and the formatter skips the tree.
- `codegen.toml` lists the core set, the curated multi-value fields, and the extras-only protocols shipped as separate `remora-<extra>` distributions under `packages/`. Extras graft leaf modules into core's `remora.proto` via `pkgutil.extend_path`; `remora.proto.__getattr__` imports installed extras lazily and raises an `ImportError` naming the extra for missing ones. `remora[all]` is the derived union of every extra (`tests/test_packaging.py` computes it rather than listing it).
- Every distribution ships its **own** `remora/py.typed` (#77); uninstalling any one of them deletes the shared marker in a wheel layout, an accepted type-checking-only price.

### Codegen: `src/remora/codegen/`

- `parse.py` turns a `tshark -G fields` dump into frozen model dataclasses; malformed, unknown, and duplicate lines become collected `ParseWarning`s (first occurrence wins), never silent drops. `tests/data/g_fields_sample.txt` is a checked-in subset of a real dump and tests assert exact record counts against it.
- `mangle.py` is the frozen abbrev → attribute-name policy. It is **not injective** (dots and hyphens both become `_`), so emitters must detect per-protocol duplicate mangled names.
- `emit.py` renders one protocol's paired `.py`/`.pyi`, byte-deterministic in input field order (so reproducible bytes require the canonicalized dump order from `fingerprint.py`). Multiplicity has no `-G fields` signal, so the multi-abbrev set is caller-supplied. Collisions resolve first-wins, except that a data field displaces an earlier `FT_NONE` marker, and every collision path records an `EmitWarning`.
- `fingerprint.py`'s `env:` line hashes only the `(name, version, type)` columns of `tshark -G plugins`, dropping the path column that embeds the multiarch triplet.

### Workspace: `src/remora/workspace/`

The M4 DuckDB workspace. `docs/workspace.md` is the user-facing account; these are the implementation invariants.

**Connection ownership.** `workspace.py` is the only module that opens a DuckDB connection. Every other module takes a caller-supplied connection. Three modules reach outside the database for what a workspace is built from, and nothing else does: `cachekey.py` reads the capture, `export.py` stats the destination, `materialize.py` runs tshark. duckdb is imported lazily inside the connect helper, so importing the package never imports duckdb (`DuckDBPyConnection` is annotated under `TYPE_CHECKING`); a missing duckdb raises `ImportError` naming `pip install 'remora[workspace]'`.

**Layout (`schema.py`).** `iter_ddl()` is the single source of the layout; `create_schema()` executes exactly those statements and is idempotent. `iter_scratch_ddl()` holds session-scoped `TEMP` DDL the layout excludes. Three tests freeze this: only `schema.py` (plus a visible `DDL_SCRATCH_FILES` exemption set for throwaway probe objects) may contain a `CREATE` head, no file but `schema.py` may create a layout name, and the heads inside `schema.py` must equal `iter_ddl()`. `SCHEMA_VERSION` is 2; `check_compatible` accepts only the exact version, there is no migration, and any column added to an existing table is a bump because `create_schema` is `IF NOT EXISTS`-only and cannot graft onto a file that already exists. `create_schema` does not imply `check_compatible`; the opener calls both. Packet data lives in `main` (`pkts`, `streams`, `annotations`), the catalog in the `meta` schema. `pkts` deliberately has **no `PRIMARY KEY`** (an ART index taxes bulk append); `frame_number` is the row key by convention. Every catalog probe is pinned to `current_database()` so an attached database cannot vouch for or collide with the current one.

**Naming and types.** `naming.column_name` keeps the **full** abbrev (unlike `codegen/mangle.py`, columns share one flat namespace), lowercases it (DuckDB identifiers are case-insensitive), and is not injective, so `find_collisions` before materializing a field set is mandatory; `meta.fields.column_name` is `UNIQUE` as backup. `naming.SKELETON_COLUMNS`/`SKELETON_ABBREVS` name the two row-key columns (`frame_number`, `frame_time`), which get no registry entry. `types.COLUMN_TYPES` is **frozen** (a column type is a storage format) and covers exactly `values.FTYPE_TABLE`'s ftype universe. Addresses are stored as integers (`FT_IPv4` → `UINTEGER`, `FT_IPv6` → `UHUGEINT`) so a subnet test is a zone-map-friendly `BETWEEN`; `FT_FLOAT` is `DOUBLE`; `FT_RELATIVE_TIME` is `INTERVAL`; `FT_ETHER` is `BLOB`; timestamps are naive UTC `TIMESTAMP`, never `TIMESTAMPTZ`, converted by `to_db_timestamp`/`from_db_timestamp`. `FT_IPv6` is the one ftype whose encoder emits decimal text rather than `int`, because DuckDB unifies a Python list's inferred element types before casting and a list mixing values below 2^63 and above 2^127 fails to bind; do not broaden it. An absent scalar encodes to `None` and an absent multi to `[]` (never `NULL` in a list column, since `list_contains(NULL, x)` is `NULL`); a scalar-declared field that occurs twice raises `ValueError`.

**Cache keys (`cachekey.py`, #27).** `fingerprint_pcap` uses `st_size`, `st_mtime_ns` and a sha256 over the first and last 64 KiB, never a whole-file digest. Its blind spot (an in-place middle edit preserving size and mtime) is pinned by a named test as an accepted trade-off. `make_cache_key` digests fingerprint, sorted-deduplicated field set, dfilter (`None` and `""` distinct), tshark version and the **full effective argv**, length-prefixed, sha256, `ck1:` scheme prefix. It returns a `CacheKeyRecord` so what was hashed and what gets written cannot drift. Hashing is total (`surrogateescape`); a lone surrogate is refused with `ValueError` before the capture is read because `VARCHAR` cannot hold it.

**Materialize (`materialize.py`, #31/#32).** `Workspace.materialize` is one `write()` transaction around `materialize_into`, so rollback and lock release are inherited from `Workspace`. A `filter` must compile fully to `-Y`; there is deliberately **no residual-predicate fallback**, because the cache key records only the dfilter. The projection always asks for `frame.time_epoch`; `frame.number`/`frame.time` get no column of their own. Rows are appended in bounded batches via `executemany`; Arrow is refused on the `FT_IPv6` hazard below. `TsharkRunner` and `tshark_version` are injectable seams so the unit suite spawns nothing. A workspace records exactly one cache key and a repeat request is decided **component by component, never digest against digest**: fingerprint, dfilter, tshark version and argv-minus-`-e`/`-r`/`-Y` must match; then requested ⊆ materialized is a **hit** (`list_has_all` in SQL), a superset is a **backfill** that rescans only the new fields and fills them by `UPDATE ... WHERE frame_number = ?` after a set-based row-key alignment check staged in a `TEMP` table, and anything else is `MaterializationMismatchError` naming each changed component. Reuse is gated on the workspace being intact: one key, key and `meta.fields` agreeing, and every registered column plus the two skeleton columns (`schema.SKELETON_COLUMN_TYPES`) present in `duckdb_columns()` with the declared type.

**Workspace class (`workspace.py`, #28).** `Workspace(path, mode="ro")` defaults to read-only because DuckDB's single-writer lock means one long-lived read-write connection blocks every other process's reads. `ro` holds one long-lived read-only connection; `rw` holds **no** connection between operations, `write()` opens one around exactly one transaction, and `read()` in rw mode opens read-write because DuckDB refuses two live same-process connections with different configurations. Consequences callers must know: an rw-mode read holds the exclusive lock for its whole duration, and a read nested in `write()` runs on its own connection and does not see uncommitted rows. rw mode runs `create_schema` only when the database holds no user objects of any kind, so a foreign file is refused rather than half-upgraded. `compact()` rewrites into a sibling `.compacting` temp via `COPY FROM DATABASE` and `os.replace`s it in while the source's exclusive lock is still held, so no commit can land in a gap and be discarded; it copies the source's mode bits onto the temp, works on the `realpath`, cleans stale temps only after acquiring the lock, and on Windows raises `WorkspaceError` naming the limitation (#85). Same-process coordination between `write()`/rw-`read()` and `compact()` is a module-level registry keyed by file **identity** (`(st_dev, st_ino)`, recomputed per operation because `compact()` swaps the inode, holding the flag under both old and new identity across the swap); it holds plain counters and a flag, never a connection. The residual: a hard-linked alias points at the old inode after a compact through another name.

**Export (`export.py`, #34).** `export_parquet(table, path)` is one `COPY ... TO (FORMAT PARQUET)` inside a `read()`, so it works in ro mode. `table` is validated against the closed `EXPORTABLE_TABLES` set (identifiers cannot be bound); the destination is compared by file identity against the database file and its `.wal` (an overwritten `.wal` is discarded silently on open, taking committed rows with it). The write goes into a private `0700` `mkdtemp` directory and is renamed onto the destination, so a link planted after the check is replaced rather than written through, and a failed `COPY` leaves the previous file intact. Two type rewrites, at list depth too: `UHUGEINT` → `VARCHAR` (duckdb writes 128-bit integers to Parquet as `double`) and `INTERVAL` → `VARCHAR` (Parquet's interval is millisecond-resolution). pyarrow is dev-only here; the export needs duckdb alone.

**Annotations (`annotations.py`, #30).** A stream annotation is keyed by `(protocol, target_id)` because tcp and udp each number streams from zero; a packet annotation by frame number alone, since one workspace holds one capture. `annotation_id` is a monotonic high-water mark in `meta.info` (`next_annotation_id`) advanced inside the caller's transaction, never a sequence (unavailable on an existing file) or `max+1` (non-unique across same-process threads, non-monotonic after a delete). A pre-existing file with annotation rows but no mark is refused rather than seeded; an empty one is seeded silently. Orphans are **kept but flagged** (`orphaned` derived at read time via EXISTS, not a join, because `pkts` has no key); `delete_orphan_annotations` is the one explicit removal and `remove_annotations` refuses a call with no filters.

**Streams (`streams.py`, #33).** `build_streams()` is one set-based `INSERT ... SELECT ... GROUP BY` per protocol, never a Python loop, keyed by `(protocol, stream_id)`. Endpoints come from the stream's first frame in one `first(... ORDER BY frame_number)` aggregate so they describe one packet; `byte_count` sums `frame.len`, matching tshark's `-z conv`. The prerequisite rule is **all of `REQUIRED_FIELDS`, both protocols', or nothing**, checked against `meta.fields` before any SQL touches `pkts` (`MissingStreamFieldsError` names the missing abbrevs). Addresses are IPv4-only and NULL is the signal for a non-IPv4 first frame; ports are unaffected. Rebuild is delete-then-reinsert inside one transaction.

**Query (`query.py`, #35).** A separate class from `Capture` on purpose: one IR, two surfaces, and the type in hand says which engine pays. Immutable and lazy; nothing touches the database until `__iter__`, `arrow()` or `sql()`. Every field the query mentions is checked against `meta.fields` before any SQL is generated (`FieldNotMaterializedError` names every missing one) and each ref's ftype/multiplicity is compared with the stored declaration (`FieldDeclarationMismatchError`) both at compile time and in `Row.get`/`get_all`, because a wrong ftype can encode to something the column holds and silently match nothing. The row key is exempt from the catalog lookup only, via the closed `_ROW_KEY_FTYPES` set, and is always projected first as ordinary `ColumnSpec`s. Decoding follows the stored `FieldRecord`, never the caller's ref. `Row` is not a `RawPacket`: access is by field ref, `row.get(IP.src)` / `row.get_all(TCP.port)`, with multiplicity checked at access time. `__iter__` `fetchall()`s inside one `read()` and decodes lazily afterwards, deliberately not streaming, because paging would hold the connection (and in rw mode the exclusive lock) across the consumer's loop and in ro mode would collide with a nested query on the one held connection. `arrow()` casts `UHUGEINT`/`UHUGEINT[]` to `VARCHAR` in the SELECT list because DuckDB exports it through Arrow as signed `decimal128(38, 0)`; pyarrow is its own extra, `remora[arrow]`. `Query` never enters the write API, pinned by a test. Parity with the pcap path is asserted operator by operator in `tests/integration/workspace/test_parity_matrix.py` (#38). `tests/integration/workspace/test_benchmark.py` (#38, `slow`) is the break-even measurement: it asserts `MIN_SPEEDUP = 5.0` for a cached repeat query against the **projected** pcap baseline (`Capture.select(...)`, `-T fields`, naming exactly the materialized field set), an order of magnitude under the measured 47-54x so a shared CI runner cannot flake it; the `-T ek` side is timed and printed but never asserted, since it bundles JSON rendering of every field into the ratio (#105). Raw SQL passthrough and joins are out of scope; `Workspace.read()` hands out the connection.

**Attach (`attach.py`, #37/#100).** Every attach is `(READ_ONLY)` in either mode, enforced by DuckDB. An attach belongs to the database *instance*, not the connection, so `rw` mode loses it between operations and `Workspace` replays recorded attachments onto every connection it opens (in `write()` before `BEGIN`). Every replayed ATTACH is validated **after** it is issued: a pre-ATTACH check describes whatever was at the path when it ran, and no metadata stamp sees an in-place rewrite that restores the mtime. Replay is all-or-nothing over the batch (`roll_back_attachments` detaches only what this replay attached). A live alias binds to the file that was attached, not the pathname; `detach` and attach again is the remedy for a replaced peer. A replay failure is translated by `Workspace` into `WorkspaceError`/`SchemaVersionError` naming the alias and path. Alias comparison is case-insensitive at the one door aliases enter through; the `_attachments` record stays case-sensitive. A colliding alias found by DuckDB's binder is classified by matching its message text (`is_duplicate_database_error`, quote-delimited and newline-free to avoid false positives) because `attach.py` never imports duckdb; a test pins the live message so a reworded duckdb fails loudly. A read-only attach takes a shared read lock for as long as a connection carrying it is open. `Query(alias=)` changes exactly the table and the `meta.fields` it validates against, and the alias is re-checked at every execution. `Query` stays single-table; a cross-capture join is ordinary SQL over `Workspace.read()`.

## Cross-cutting invariants

- `tests/test_proto_seed.py` pairing tests are the frozen-format contract for generated modules. Keep them passing unmodified.
- Attribute names come from the frozen mangle policy at generation time; `_table_` stores the full tshark name precisely so nothing at runtime may re-derive tshark names from attribute names or vice versa.
- Absence is `()` from `get_raw`, `None` from scalar instance access, `()` from multi instance access — never an exception, except `FieldNotProjectedError` for fields outside a `-T fields` projection.
- Underscore-prefixed attributes on protocol classes are reserved; ruff RUF012 requires the `ClassVar[FieldTable]` annotation on tables.
- Loud beats silent, everywhere: parse errors raise, non-injective naming policies are checked and refused, a stale or foreign workspace file is refused at open, and a backend that cannot express an expression raises its `Unsupported*` error rather than approximating.
- Storage-format changes (a column type, a layout column, a cache-key scheme, a separator byte) are never tweaks: they bump `SCHEMA_VERSION` or the key scheme prefix so older files are refused visibly instead of misread.
- `tests/conftest.py` provides `FakePacket`, the standard `RawPacket` test double, and the CI dependency guard: workspace suites gate on `pytest.importorskip("duckdb", ...)`, while `REMORA_REQUIRE_DUCKDB=1` and `REMORA_REQUIRE_TSHARK=1` (set in `.github/workflows/ci.yml`) make `pytest_configure` refuse the run outright so a broken CI install fails rather than silently skipping.
