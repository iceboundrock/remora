# src/remora/workspace/AGENTS.md

`docs/workspace.md` is the user-facing account, and a change here belongs there too. These are the implementation invariants. The SQL backend this package queries through is `src/remora/compile/sql.py`, whose rules are in `src/remora/compile/AGENTS.md`.

The first three sections bind every module here. The rest are per module.

## Connections

`workspace.py` is the only module that opens a DuckDB connection; every other module takes one. Only five modules reach outside the database: `cachekey.py` reads the capture, `export.py` stats the destination, `materialize.py` runs tshark, `swap.py` renames compact's temp into place, and `permissions.py` gives that temp the workspace file's restrictions. duckdb is imported lazily inside the connect helper, so importing the package never imports it, and a missing duckdb raises `ImportError` naming `pip install 'remora[workspace]'`.

## Layout (`schema.py`)

- `iter_ddl()` is the single source of the layout, and `create_schema()` executes exactly those statements, idempotently. `iter_scratch_ddl()` holds session-scoped `TEMP` DDL. Tests freeze this: only `schema.py` (plus the visible `DDL_SCRATCH_FILES` exemption set) may contain a `CREATE` head, and the heads inside `schema.py` must equal `iter_ddl()`.
- `SCHEMA_VERSION` is 4, `check_compatible` accepts only the exact version, and there is no migration. Any column added to an existing table is a bump, because `create_schema` is `IF NOT EXISTS`-only. So is a change to what a stored value means with no DDL change at all: version 3 (#117) changed the instant a pre-1970 fractional `frame.time_epoch` reads as, and a version 2 file would otherwise be reused as a cache hit holding the old instants. Version 4 (#69) retyped `FT_GUID` columns to `UUID` and `FT_EUI64` to `BLOB`; a version 3 file's registry and columns agree with each other, so only the version row refuses it. The opener calls both `create_schema` and `check_compatible`, and every attach runs `check_compatible` against the alias.
- Packet data lives in `main` (`pkts`, `streams`, `annotations`) and the catalog in `meta`. `pkts` has no `PRIMARY KEY`, because an ART index taxes bulk append; `frame_number` is the row key by convention. Every catalog probe is pinned to `current_database()` so an attached database cannot vouch for or collide with the current one.

## Naming and types (`naming.py`, `types.py`)

- `naming.column_name` keeps the full abbrev, lowercased, and is not injective, so `find_collisions` before materializing a field set is mandatory, with `meta.fields.column_name UNIQUE` as backup. The row-key columns `frame_number`/`frame_time` (`naming.SKELETON_COLUMNS`) get no registry entry.
- `types.COLUMN_TYPES` is frozen, because a column type is a storage format, and it covers exactly `values.FTYPE_TABLE`. Addresses are integers (`FT_IPv4` → `UINTEGER`, `FT_IPv6` → `UHUGEINT`) so a subnet test is a zone-map-friendly `BETWEEN`. `FT_GUID` is DuckDB `UUID`, whose order is `uuid.UUID`'s, and `FT_EUI64` is `BLOB` like `FT_ETHER`. Timestamps are naive UTC `TIMESTAMP`, never `TIMESTAMPTZ`.
- `FT_IPv6` alone encodes to decimal text rather than `int`, because DuckDB unifies a list's inferred element types before casting and a list mixing values below 2^63 and above 2^127 fails to bind. Do not broaden it. An absent scalar encodes to `None` and an absent multi to `[]`, since `list_contains(NULL, x)` is `NULL`. A scalar-declared field occurring twice raises `ValueError`.

## Cache keys (`cachekey.py`, #27)

`fingerprint_pcap` hashes `st_size`, `st_mtime_ns` and the first and last 64 KiB, not the whole file. Its blind spot, an in-place middle edit preserving size and mtime, is pinned by a named test as an accepted trade-off. `make_cache_key` digests fingerprint, sorted-deduplicated field set, dfilter (`None` and `""` distinct), tshark version and the full effective argv under the `ck1:` prefix. It returns a `CacheKeyRecord` so what was hashed and what gets written cannot drift. A lone surrogate is refused with `ValueError` before the capture is read, because `VARCHAR` cannot hold it.

## Materialize (`materialize.py`, #31/#32)

- One `write()` transaction wraps `materialize_into`. A `filter` must compile fully to `-Y`. There is no residual-predicate fallback, because the cache key records only the dfilter.
- The projection always asks for `frame.time_epoch`; `frame.number`/`frame.time` get no column. Rows are appended in bounded `executemany` batches, and Arrow is refused because of the `FT_IPv6` hazard. `TsharkRunner` and `tshark_version` are injectable so the unit suite spawns nothing.
- A workspace records exactly one cache key, and a repeat request is decided component by component rather than digest against digest. Fingerprint, dfilter, tshark version and argv-minus-`-e`/`-r`/`-Y` must match. Then requested ⊆ materialized is a **hit**, a superset is a **backfill** (rescan only the new fields, then `UPDATE ... WHERE frame_number = ?` after a set-based row-key alignment check), and anything else is `MaterializationMismatchError` naming each changed component.
- Reuse requires an intact workspace: one key, key and `meta.fields` agreeing, and every registered plus skeleton column present in `duckdb_columns()` with the declared type.

## Workspace class (`workspace.py`, #28)

- **Modes.** `Workspace(path, mode="ro")` defaults to read-only because one long-lived read-write connection blocks every other process's reads under DuckDB's single-writer lock. `ro` holds one long-lived read-only connection. `rw` holds none between operations: `write()` opens one around exactly one transaction, and `read()` in rw mode opens read-write because DuckDB refuses two live same-process connections with different configurations. So an rw-mode read holds the exclusive lock for its whole duration, and a read nested in `write()` runs on its own connection and does not see uncommitted rows. rw mode runs `create_schema` only on a database with no user objects of any kind, so a foreign file is refused rather than half-upgraded.
- **`compact()`** rewrites into a temp via `COPY FROM DATABASE` and renames it in while the source's exclusive lock is still held, so no commit can land in a gap and be discarded. The work happens on the `realpath`. Each compact creates its own staging directory beside it with `os.mkdir(..., 0o700)` under a fresh name, `remora-compact-<16 hex digits>` (a taken name is skipped, never reused), and writes a `remora-compact` marker naming the workspace into it. The name is fixed-length and never embeds the workspace's, so a workspace name near the 255-byte component limit still compacts and no workspace name can collide with the marker; only the marker says whose a staging directory is. On POSIX the temp `compact.duckdb` and its `.wal` are inside it; on Windows the temp is the sibling `<staging name>.tmp`, one already there (or at its `.wal`) refuses the compact, and once `ATTACH` has created it a `temp-claim` file inside records its `(st_dev, st_ino)`. A derived pathname never establishes ownership, and the source's lock does not cover other paths: compact removes only its own temp and staging directory, and, under the lock, stale staging directories that `_is_own_stale_staging` proves are this workspace's (a real directory at an exact staging name, owned by this user on POSIX, holding the marker and only the files a compact creates). A stale Windows sibling temp is removed only while it is the regular file the claim names (`_stale_temp_files`): no claim (killed before it was written) or a different file (the swap renamed the temp away) leaves it alone. The Windows temp's `.wal` is never removed, stale or by a failing compact (`_own_temp_files`): no claim covers a separate file at a derived name, and one created after a detach deleted DuckDB's own would be someone else's. `_TEMP_BESIDE_STAGING` selects the Windows layout and is read at call time, so tests run it on every platform. Everything else is left alone, including an older remora's fixed `<name>.compacting`. Removal is entry by entry, never a tree, with the marker last. A failed compact cleans up before its connection closes; a successful one removes its marker-only staging directory after the swap, which is safe because no other compact uses that name. `DETACH` checkpoints the temp; a temp `.wal` that survives it refuses the swap, because only the database file is renamed.
- **Temp permissions (`permissions.py`).** The temp gets the source's mode bits, and on Windows its DACL with its inheritance setting (`permissions.copy_permissions`, #132), right after `ATTACH` creates it and before `COPY` writes a row. A failure there refuses the compact rather than copying into a file wider than the workspace. That sets the compacted file's restrictions; it does not protect the temp while it fills. That is the staging directory's job on POSIX, where a `chmod` cannot revoke a descriptor opened before it and the `.wal` never gets one, and DuckDB's share mode's on Windows. Windows stays on the in-place temp on purpose (#147): a file moved on NTFS keeps the ACEs it inherited from the staging directory, and `mkdtemp` is private there only from CPython 3.12.4.
- **The boundary is the directory (#147).** DuckDB creates the workspace's own `.wal` with the process defaults (a `0o600` database gets a `0o644` `.wal` under umask `022`) and writes committed rows into it, with no hook for remora in between. Do not add a `chmod`-after-create (the same TOCTOU) or a process-wide `umask` change (not thread-safe) as a fix, and never change the caller's directory permissions. The strict `xfail` in `tests/test_workspace_permissions.py` pins the DuckDB behaviour; when it starts passing, revisit the boundary in `docs/workspace.md` and the `compact()` docstring, which state it in the same terms.
- **Swap (`swap.py`).** The swap is `swap.replace_file`: `os.replace` on POSIX and a `FileRenameInfoEx` POSIX-semantics rename on Windows, which works under the open connection because duckdb ≥ 1.5.0 opens the file with `FILE_SHARE_DELETE`; a sharing violation (Windows error 32, such as an older duckdb or a handle without delete sharing) or a volume without POSIX rename semantics gets a `WorkspaceError` naming the requirement (#85). Access denied (Windows error 5) propagates as the original `PermissionError`, since it may mean missing delete permission on the workspace file and its directory rather than a sharing conflict. Do not fall back to `os.replace` on Windows: under the lock it fails with a misleading access-denied.
- **Same-process coordination** between `write()`/rw-`read()` and `compact()` is a module-level registry of counters and a flag, not a connection, keyed by file identity (`(st_dev, st_ino)`). The identity is recomputed per operation because `compact()` swaps the inode and holds the flag under both identities across the swap. What remains uncovered is a hard-linked alias, which points at the old inode after a compact through another name.

## Export (`export.py`, #34)

- `export_parquet(table, path)` is one `COPY ... TO (FORMAT PARQUET)` inside a `read()`, so it works in ro mode. `table` is validated against the closed `EXPORTABLE_TABLES` set, because identifiers cannot be bound.
- The destination is compared by file identity against the database file and its `.wal`, since an overwritten `.wal` is discarded silently on open and takes committed rows with it. The write goes into a private `0700` `mkdtemp` directory and is renamed onto the destination, so a link planted after the check is replaced rather than written through, and a failed `COPY` leaves the previous file intact.
- Two types are rewritten, at list depth too: `UHUGEINT` → `VARCHAR`, because duckdb writes 128-bit integers to Parquet as `double`, and `INTERVAL` → `VARCHAR`, because Parquet's interval is millisecond-resolution. The export needs duckdb alone; pyarrow is dev-only here.

## Annotations (`annotations.py`, #30)

- A stream annotation is keyed by `(protocol, target_id)` because tcp and udp each number streams from zero. A packet annotation is keyed by frame number alone, since one workspace holds one capture.
- `annotation_id` is a high-water mark in `meta.info` (`next_annotation_id`) advanced inside the caller's transaction. It is not a sequence, which is unavailable on an existing file, and not `max+1`, which is non-unique across threads and non-monotonic after a delete. A pre-existing file with annotation rows but no mark is refused rather than seeded; an empty one is seeded silently.
- Orphans are kept but flagged. `orphaned` is derived at read time via EXISTS rather than a join, because `pkts` has no key. `delete_orphan_annotations` is the one explicit removal, and `remove_annotations` refuses a call with no filters.

## Streams (`streams.py`, #33)

- `build_streams()` is one set-based `INSERT ... SELECT ... GROUP BY` per protocol, not a Python loop, keyed by `(protocol, stream_id)`. Endpoints come from the stream's first frame in one `first(... ORDER BY frame_number)` aggregate so they describe one packet, and `byte_count` sums `frame.len` to match `tshark -z conv`.
- The prerequisite rule is all of `REQUIRED_FIELDS`, both protocols', or nothing, checked against `meta.fields` before any SQL touches `pkts`; `MissingStreamFieldsError` names the missing abbrevs. Addresses are IPv4-only, and NULL marks a non-IPv4 first frame. Rebuild is delete-then-reinsert inside one transaction.

## Query (`query.py`, #35)

- It is a separate class from `Capture` on purpose: one IR, two surfaces, and the type in hand says which engine pays. It is immutable and lazy, and nothing touches the database until `__iter__`, `arrow()` or `sql()`.
- Every field the query mentions is checked against `meta.fields` before any SQL is generated, and `FieldNotMaterializedError` names every missing one. Each ref's ftype and multiplicity are compared with the stored declaration (`FieldDeclarationMismatchError`) both at compile time and in `Row.get`/`get_all`, because a wrong ftype can encode to something the column holds and silently match nothing. The row key alone skips the catalog lookup (`_ROW_KEY_FTYPES`) and is always projected first. Decoding follows the stored `FieldRecord`, not the caller's ref.
- `Row` is not a `RawPacket`: access is `row.get(IP.src)` / `row.get_all(TCP.port)`, with multiplicity checked at access time.
- `__iter__` calls `fetchall()` inside one `read()` and decodes afterwards. It deliberately does not stream, because paging would hold the connection (in rw mode, the exclusive lock) across the consumer's loop and in ro mode would collide with a nested query on the one held connection. `arrow()` casts `UHUGEINT`/`UHUGEINT[]` to `VARCHAR` because DuckDB exports it through Arrow as signed `decimal128(38, 0)`; pyarrow is the `remora[arrow]` extra.
- `Query` never enters the write API, and a test pins that. Parity with the pcap path is asserted operator by operator in `tests/integration/workspace/test_parity_matrix.py` (#38), and `tests/AGENTS.md` covers it and the speedup benchmark. Raw SQL passthrough and joins are out of scope; `Workspace.read()` hands out the connection.

## Attach (`attach.py`, #37/#100)

- Every attach is `(READ_ONLY)` in either mode. An attach belongs to the database instance, not the connection, so `rw` mode loses it between operations and `Workspace` replays recorded attachments onto every connection it opens (in `write()` before `BEGIN`).
- Each replayed ATTACH is validated **after** it is issued, since a pre-ATTACH check only describes whatever was at the path when it ran. Replay is all-or-nothing over the batch (`roll_back_attachments`), and a replay failure becomes `WorkspaceError`/`SchemaVersionError` naming the alias and path. A live alias binds to the file that was attached, not the pathname, so `detach` and attach again is the remedy for a replaced peer.
- Alias comparison is case-insensitive at the one door aliases enter through, while the `_attachments` record stays case-sensitive. A colliding alias found by DuckDB's binder is classified by message text (`is_duplicate_database_error`) because `attach.py` never imports duckdb, and a test pins the live message so a reworded duckdb fails loudly.
- A read-only attach holds a shared read lock while a connection carrying it is open. `Query(alias=)` changes exactly the table and the `meta.fields` it validates against, re-checked at every execution. `Query` stays single-table; a cross-capture join is ordinary SQL over `Workspace.read()`.
